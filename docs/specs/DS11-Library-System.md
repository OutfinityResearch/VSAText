# DS11 — Library System and Reusable Narrative Assets

## Purpose

This document defines the SCRIPTA Library system and the reusable narrative assets it provides. Its role is to describe which asset categories exist, how they are applied in projects, and how reuse supports planning, specification, and drafting workflows.

## What the Library Is

The Library is SCRIPTA's reusable asset system. It allows authors to browse predefined narrative elements and apply them to a project instead of defining every story element from scratch.

The Library supports consistency, faster setup, and structured reuse. It is intended to help authors work with narrative building blocks while preserving project-level control.

## Asset Categories

The Library may include reusable assets such as character archetypes, themes, patterns, locations, objects, and tone or style guidance. Each asset type contributes a different part of the narrative specification.

Character assets provide reusable role and trait templates. Pattern assets provide structural guidance such as three-act or hero's journey models. Theme assets provide reusable thematic directions. Location and object assets provide reusable world elements. Tone and style assets provide reusable drafting guidance.

## Application Scope

Library assets can be applied at different levels depending on category and intent.

| Scope | Description |
|-------|-------------|
| Book | Applies the asset to the whole project or global story foundation |
| Chapter | Applies the asset to a chapter-level planning unit |
| Scene | Applies the asset to a scene-level planning or generation unit |

Not every asset category must support every scope. The supported scope depends on the asset type and the workflow where it is used.

## Application Workflow

The standard Library workflow is:

1. Open Library from a relevant page or open Library directly.
2. Select a reusable asset.
3. Review the asset content and intended effect.
4. Choose an application scope such as `Book`, `Chapter`, or `Scene` when supported.
5. Apply the asset.
6. Continue editing in the destination workflow.

Applying a Library item should accelerate authoring without preventing later manual edits.

## Relationship to Project Data

Library assets are templates, not final project truth. Once applied, their content becomes part of the working project state and may be modified by the author.

The source Library asset remains reusable. The applied project content may diverge from the original template over time.

## Relationship to CNL and Planning

Library assets support the planning workflow and may contribute to the formal story specification. They help populate project structures such as character definitions, world elements, thematic guidance, or structural patterns that later influence Blueprint, CNL Editor, and NL Story.

The Library does not replace planning. It accelerates planning by providing reusable starting points.

## Example Asset Families

| Asset Family | Typical Use |
|--------------|-------------|
| Character Archetypes | Reusable role and trait templates for cast creation |
| Story Patterns | Reusable structural templates for plot planning |
| Themes | Reusable thematic directions and moral questions |
| Locations | Reusable setting components and world anchors |
| Objects | Reusable props, artifacts, and symbolic items |
| Tone and Style | Reusable voice and prose guidance |

## Success Criteria

The Library system is successful when:

- reusable assets can be applied without breaking project flow
- authors can use Library items to accelerate planning and drafting
- applied assets remain editable at project level
- Library reuse improves consistency without forcing rigid templates
