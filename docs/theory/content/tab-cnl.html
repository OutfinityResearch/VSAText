CNL Editor

The CNL Editor displays and edits the generated formal specification for your story. It sits between Blueprint and NL Story and exposes the machine-readable structure that powers analysis, generation, and verification.

When to Use This Page

Use CNL Editor after Blueprint. Review it when you want to confirm that the story plan has been translated correctly into formal structure, export the specification, or make precise corrections.

What This Tab Does

The CNL Editor shows the CNL generated from your visual editor inputs. Every character, location, relationship, chapter, scene, beat mapping, hook, dialogue, and constraint defined through the UI is converted into CNL syntax.

Key Features

  • CNL View: visual formatted mode for reading the current specification in structured sections
  • Edit: direct text editing when precise fixes are needed
  • Import / Export: move CNL in and out of the project
  • Debugging Surface: inspect how UI decisions map into formal specification
  • Readable IDs: dialogue entries are displayed with simple labels such as D1, D2, D3 in the visual view for easier review

In the current workflow, CNL is not the first planning step. Blueprint establishes the structural logic first, and CNL lets you inspect that logic in formal, portable form before prose generation begins.

Understanding the CNL Structure

The generated CNL follows a consistent pattern:

// Entity Definitions
EntityName is type
EntityName has property value

// Relationships
Entity1 relates to Entity2 as relationship_type

// Story Structure
"Book Title" is book
  "Chapter 1" is chapter
    "Scene 1" is scene at Location
      Character does action

CNL Sections

Section Contains Generated From
Entities Characters, locations, objects Cast and World pages
Relationships Character connections Relations tab
Moods Emotional atmospheres Story Core, Blueprint, and related planning pages
Themes & Wisdom Thematic content Story Core
World Rules Universe constraints Story Core and World
Blueprint Arc, beats, tension curve, hooks, and structural mapping Blueprint tab
Structure Books, chapters, scenes Story Map and Manuscript structure
Blocks Reusable story patterns (Revelation, Confrontation, Sacrifice, etc.) Blocks tab
Dialogues Dialogue entries, beat links, tone, tension, speaker, and listener data Blueprint and scene structure

What to Review Here

  • Beat Mappings: verify that the selected arc and beat names match the intended structure.
  • Dialogues: confirm that each dialogue is attached to the correct beat, purpose, tone, and participants.
  • Hooks: verify that opening and mid-story hooks point to valid target scenes and beats.
  • Book Structure: confirm that chapters, scenes, relationships, and key dialogues reflect the current Blueprint.

Blueprint Synchronization

CNL is derived from the project state. When Blueprint changes, the CNL view should change too.

  • Changing the narrative arc updates beat mappings in CNL.
  • Arc changes also propagate to related dialogue beat references and hook targets.
  • Scene and chapter titles may change when they are still auto-generated from structural beats.

If the CNL no longer matches your intended story logic, the first place to inspect is usually Blueprint rather than the raw CNL text.

Common Use Cases

1. Debugging

When metrics show unexpected values, check the CNL to verify that beats, dialogues, hooks, characters, and scenes are correctly defined.

2. Backup

Export CNL regularly to have a text-based backup of your story specification.

3. Sharing

Share CNL files with collaborators who can import them into their own SCRIPTA instance.

4. Advanced Editing

Most work should happen in the UI, but direct CNL editing is useful for precise fixes or specification cleanup.

Metrics Impact

The CNL Editor itself does not calculate metrics, but the specification shown here is exactly what validation and generation depend on. Reviewing it helps explain why coherence, coverage, and structural metrics behave the way they do.
